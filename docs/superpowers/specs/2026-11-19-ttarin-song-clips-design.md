# 따린 노래 클립 사이트 — 설계

작성일: 2026-11-19 · 개정: 2026-11-19(방송 정보 기반 분류·무대 묶기, 사용자 승인)

## 1. 목적

SOOP 방송인 **insome0319(따린)** 채널에 시청자가 올린 클립 가운데 **따린님이 노래를 부른 클립**을 모아 분류·정리하고, 팬들이 곡명·가수로 검색해 보는 **공개 팬 사이트**를 만든다.

### 성공 기준
- 곡명, 원곡 가수, 함께 부른 사람으로 검색하면 해당 클립(무대 단위로 묶임)이 나온다.
- 결과를 **최신순 / 조회수순**으로 정렬하고 **전체 / 솔로 / 듀엣**으로 거를 수 있다.
- 새 클립과 조회수가 **하루 한 번 자동** 반영되고, 관리자가 **버튼으로 즉시** 가져올 수 있다.
- 자동 분류 결과를 관리자가 고칠 수 있고, 고친 값은 자동 갱신이 덮어쓰지 않는다.
- 첫 화면에 **조회수 TOP 10**(이번 주 / 이번 달 / 전체)과 **많이 부른 곡 TOP 10**이 보인다.
- 곡 페이지와 가수 페이지가 있고, 곡명·가수 이름을 누르면 이동한다.
- 클립을 사이트 안에서 재생한다(실패하면 SOOP 링크).
- 운영 비용 0원(Vercel 무료 플랜 범위).

## 2. 범위

### 포함
- 따린님이 부른 노래 클립: 솔로, 그리고 둘 이상이 함께 부른 무대(= **듀엣**, 3인 이상 합동 포함)
- 공개 사이트: 첫 화면(플레이어 고정 + 목록 + 순위), 곡 페이지, 가수 페이지(원곡 가수·함께 부른 사람)
- 관리자 화면(비밀번호 1개, 관리자 1명)
- 수집기: 첫 전체 수집, 매일 자동 갱신, 수동 갱신

### 제외 (나중에 추가 가능)
- 반응 클립, 저스트댄스 클립, 다른 사람만 부른 클립
- 관리자 여러 명 / 수정 기록
- 광고·후원 등 상업 기능(Vercel 무료 플랜은 비상업 전용)

## 3. 데이터 출처 (2026-11-18 확인)

## 4. 구조

```
[SOOP 클립 API] ──(Vercel Cron 하루 1회 / 관리자 버튼)──▶ [수집기]
                                                         │ 제목 분석 → 곡·부른 사람·노래 여부
                                                         │ 곡 연결 · 무대 묶기
                                                         ▼
                                              [Postgres (Neon, Vercel 마켓플레이스)]
                                                         │
                     ┌───────────────────────────────────┴──────────────┐
                     ▼                                                  ▼
          [공개 사이트] 검색·필터·정렬·순위·재생        [관리자 화면] 확인 필요, 수정, 곡/무대 합치기, 지금 가져오기
```

- **Next.js(App Router) 앱 하나**를 Vercel에 배포한다. 공개 페이지, 관리자 페이지, 수집 API가 같은 앱에 있다.
- 데이터베이스는 Vercel 마켓플레이스의 **Neon Postgres**(무료). 몇 분 쉬면 잠들고 요청 시 깨어나며(첫 요청 1초 미만 지연), 데이터는 유지된다.
- 무료 플랜 세부 조건(Cron 횟수, 함수 실행 시간, DB 용량)은 구현 시점에 다시 확인한다.

## 5. 데이터 구조

### clips — SOOP 클립 1개
| 필드 | 설명 |
|---|---|
| `title_no` (PK) | SOOP 클립 번호 |
| `title_raw` | 원래 제목 |
| `uploader_nick`, `uploader_id` | 올린 시청자 |
| `reg_date` | 등록 시각 |
| `read_cnt` | 조회수 |
| `thumb_url`, `duration_ms` | 썸네일, 길이 |
| `status` | `auto`(자동 분류·공개) / `review`(확인 필요·비공개) / `not_song`(노래 아님) / `confirmed`(관리자 확인·공개) / `gone`(SOOP에서 삭제됨·비공개) |
| `song_id` (FK, null 가능) | 연결된 곡 |
| `performers` | 부른 사람 목록(따린 포함) |
| `is_duet` | 부른 사람이 2명 이상이면 참 (자동 계산) |
| `performance_id` (FK) | 묶인 무대 |
| `locked` | 관리자가 고쳤으면 참 → 자동 갱신은 조회수·썸네일만 바꿈 |
| `first_seen_at`, `views_updated_at` | 수집 기록 |

### songs — 곡
| 필드 | 설명 |
|---|---|
| `id` (PK), `slug` | 곡 페이지 주소용 |
| `title`, `title_norm` | 곡명, 비교용 정규화 곡명(소문자·공백/기호 제거) |
| `original_artist`, `artist_norm` | 원곡 가수(비어 있을 수 있음) |

곡명 정규화가 같고 원곡 가수가 같으면(또는 한쪽이 비었으면) 같은 곡으로 본다. 자동으로 못 합친 중복은 관리자가 **곡 합치기**로 처리한다.

### performances — 무대(같은 무대를 찍은 클립 묶음)
| 필드 | 설명 |
|---|---|
| `id` (PK), `song_id` | |
| `started_at` | 묶인 클립 중 가장 이른 등록 시각 |
| `best_clip_no` | 조회수가 가장 높은 클립(대표) |
| `locked` | 관리자가 합치거나 나눴으면 참 |

**자동 묶기 규칙(개정)**: 같은 곡이고 같은 원본 다시보기에서 **10분(600초) 이내** 지점을 딴 클립이면 같은 무대. 원본 정보가 없으면 예전 규칙(등록 시각 **3시간 이내**)을 쓴다. 해당이 없으면 새 무대.

### sync_runs / sync_state
- `sync_runs`: 실행마다 시작·종료 시각, 종류(자동/수동/첫 수집), 새 클립 수, 조회수 갱신 수, 오류 메시지.
- `sync_state`: 첫 수집 진행 위치, 오래된 클립 조회수 순환 갱신 위치.

## 6. 자동 분류 규칙

순서대로 적용한다.

1. **노래 아님 거르기**: 제목에 `반응`, `저스트댄스`, `풀트`, `더빙`이 있거나 `A - B` 꼴(하이픈 구분)이 없으면 `not_song`.
2. **꾸밈 제거**: `[클립]`, `[로이세끼2]` 같은 대괄호 태그, `(짧)`, `(더블링)`, `[더블링]` 같은 메모를 뗀다.
3. **양쪽 판별**: ` - `로 나눠, `따린` / `Cover` / `x`·`×`·`&`로 이어진 이름이 있는 쪽을 **부른 사람**, 반대쪽을 **곡명**으로 본다.
4. **부른 사람 확인**: 이름을 나눠 `따린`이 있으면 통과. 없으면(예: `안동역에서 - 구슬요 Cover`) `not_song`.
5. **원곡 가수**
   - `Coldplay - Viva La Vida`처럼 한쪽이 따린이 아닌 가수명이면 → 원곡 가수. 이때 부른 사람은 확실하지 않으므로 `review`.
   - `곡명(가수)` 괄호 → 원곡 가수.
   - 없으면 같은 정규화 곡명의 기존 곡에서 가져온다.
   - 그래도 없으면 비워 둔다(관리자 "원곡 가수 없음" 목록).
6. **애매하면 `review`**: 판단 근거가 약한 경우(위 5의 첫 경우, 곡명이 비거나 너무 짧은 경우 등).
7. **방송 정보로 판단(개정)**: 노래 후보와 "다른 사람이 부름" 신호가 있는 클립은 상세 정보를 받아 원본 방송을 기록한다.
   - 같은 원본 다시보기에 **다른 사람이 따린님 없이 부른** 신호(함께 부른 사람만 적힌 제목, 대괄호의 다른 이름, `이름 Cover`)가 하나도 없으면 **혼자 한 방송**이다. 따린님이 함께 부른 듀엣은 신호가 아니다. 그 방송의 `가수 - 곡명` 확인 필요 클립은 따린님이 부른 것으로 **자동 공개**한다(`via_broadcast`).
   - 나중에 같은 방송에서 합방 신호가 나오면, 방송 정보로 자동 공개했던 클립(잠기지 않은 것)을 다시 확인 필요로 돌린다.
   - 다른 사람 방송에서 딴 클립은 이 규칙을 쓰지 않는다.

- 분류 규칙은 실제 제목 수천 개로 시험해 `review` 비율을 측정하고, 대표 제목 형식은 자동 테스트로 고정한다.
- 공개 사이트에는 `auto`와 `confirmed`만 보인다.

## 7. 수집기

### 첫 전체 수집
- 기간(예: 3개월 단위)으로 나눠 모든 쪽을 받는다. 총 요청 약 420번.
- 한 번 실행에 일부 기간만 처리하고 `sync_state`에 위치를 저장해 이어간다(함수 실행 시간 제한 대비). 관리자 화면의 버튼이나 로컬 스크립트로 반복 실행해 끝낸다.

### 매일 자동 갱신 (Vercel Cron, 하루 1회)
1. **새 클립**: 최신순으로 받다가 이미 저장된 클립이 한 쪽 전체에 나오면 멈춘다.
2. **최근 조회수**: 최근 90일 클립을 기간 조회로 다시 받아 조회수를 갱신한다.
3. **오래된 조회수**: 90일보다 오래된 기간을 하루에 일부씩 돌아가며 갱신한다(약 2주에 한 바퀴).
4. **삭제 확인**: 다시 받은 기간에 없는 클립은 `gone`으로 바꾼다(관리자 수정값은 보존).
5. 새 클립은 분류 → 곡 연결 → 무대 묶기를 거쳐 저장한다.

### 수동 갱신
- 관리자 버튼은 매일 갱신과 같은 작업을 즉시 실행한다. 이미 실행 중이면 겹쳐 실행하지 않는다.

### SOOP 배려
- 요청 사이 간격을 두고, 동시 요청은 최대 2개. 하루 요청 수는 수백 번 이내.
- 상세 정보는 노래 후보와 합방 신호 클립에만 받는다(노래 아닌 클립 약 70%는 건너뜀). 상세 요청도 실행 예산·기한에 포함된다.

## 8. 공개 사이트

### 공통
- 분위기: **흰 바탕 + 파란 헤더**, 대표색 파랑·검정(검정은 글자·강조에). 다크 모드 자동 지원. 정확한 파랑 값은 대표색을 받으면 맞춘다.
- 한글 글꼴(예: Pretendard). 휴대폰·PC 모두 지원.
- 곡명·가수 이름은 어디서든 해당 페이지로 링크된다.

### 첫 화면 `/`
- **위**: 파란 헤더 + 고정 플레이어(SOOP 임베드). 재생 실패 시 "SOOP에서 보기" 링크.
- **목록**: 검색창(곡명·원곡 가수·함께 부른 사람) → 필터 `전체 / 솔로 / 듀엣` → 정렬 `최신순 / 조회수순`.
  - 한 줄 = **무대 하나**. "클립 N개 ▾"를 펼치면 클립별로 재생할 수 있다.
  - 무대의 조회수 = 대표 클립(최고 조회수)의 조회수. 무대의 날짜 = `started_at`.
  - 검색·필터·정렬 상태는 주소에 담아 공유할 수 있게 한다(예: `/?q=memories&type=duet&sort=views`).
- **순위**(PC는 오른쪽, 휴대폰은 검색창 위 가로 스크롤)
  - **조회수 TOP 10**: 이번 주 / 이번 달 / 전체. 무대마다 대표 클립 하나만 넣는다.
  - **많이 부른 곡 TOP 10**: 곡별 무대 수 기준.

### 곡 페이지 `/song/[slug]`
- 곡명, 원곡 가수(링크), 무대 수, 클립 수.
- 무대 목록(날짜·솔로/듀엣·함께 부른 사람·클립 수·최고 조회수), 정렬 `무대별(최신) / 조회수순`.

### 가수 페이지 `/artist/[slug]`
- 원곡 가수: 따린님이 부른 그 가수의 곡 목록과 곡별 무대 수.
- 함께 부른 사람: 따린님과 함께 부른 곡·무대 목록. 같은 페이지 모양을 쓴다.

## 9. 관리자 화면 `/admin`

- 비밀번호 로그인(환경변수 `ADMIN_PASSWORD`), 로그인 시도 횟수 제한, 로그인 상태는 서명된 쿠키.
- **상단 상태줄**: 마지막 갱신 시각·결과, 최근 실패 기록, **지금 가져오기** 버튼, 첫 수집 진행률.
- **탭**: 확인 필요 / 원곡 가수 없음 / 공개 중 / 노래 아님 (숫자 표시), 제목 검색.
- **표에서 바로 수정**: 곡명·원곡 가수·부른 사람, 미리보기 재생. 수정하면 `locked`.
- **일괄 처리**: 여러 개 선택 → 승인(공개) / 노래 아님.
- **같은 곡 일괄 적용**: 원곡 가수를 바꾸면 같은 정규화 곡명의 다른 클립에도 적용할지 묻는다.
- **곡 합치기**: 중복 곡 둘을 하나로.
- **무대 합치기 / 나누기**: 자동 묶기가 틀렸을 때.

## 10. 오류 대비와 보안

- 수집 실패 시 기존 데이터 유지, 실패 기록 표시, 다음 갱신 때 자동 재시도.
- 응답 형식 검사(필수 필드·타입). 예상과 다르면 저장하지 않고 중단한다.
- Cron 엔드포인트는 `CRON_SECRET`으로 보호(Vercel Cron 전용).
- 관리자 API는 로그인 쿠키 확인. 비밀값은 모두 Vercel 환경변수.

## 11. 시험

- **분류 규칙**: 실제 제목 샘플로 측정, 대표 형식 단위 테스트(솔로·듀엣·원곡가수 표기·괄호·반응·저스트댄스·다른 사람만 부름).
- **곡 연결·무대 묶기**: 정규화, 3시간 규칙, 관리자 잠금 보존.
- **수집기**: 저장해 둔 SOOP 응답(가짜 데이터)으로 새 클립, 조회수 갱신, 잠금 보존, 삭제 처리, 형식 오류 시 중단.
- **검색·필터·정렬·순위**: 테스트 데이터베이스로 검증.
- **화면**: 실제 데이터로 휴대폰·PC 확인 후 디자인 다듬기.

## 12. 열린 문제

- 대표 파랑 색상 값(받으면 반영).
- 사이트 이름과 주소(기본 `xxx.vercel.app`).
- `review` 비율이 높으면 분류 규칙 추가 조정.
- SOOP 비공식 API 변경 시 수집기 수정 필요.
