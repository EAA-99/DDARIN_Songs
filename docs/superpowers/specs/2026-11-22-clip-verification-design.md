# 설계: 자동 공개 전에 "진짜 있는 곡인지" 확인하기 + 관리자 로그인 버튼

날짜: 2026-11-22 · 상태: 승인됨

## 목표

- 잡담 클립이 노래로 자동 공개되는 일을 줄인다. 예: "따린 놀리기 -1"이 곡 "1"로, "[클립]머독 하이드로펌프-따린"이 곡 "머독 하이드로펌프"로 공개된 경우.
- 진짜 노래는 지금처럼 자동 공개하고, 원곡 가수도 더 많이 자동으로 채운다(관리자 손을 덜 가게).
- 사이트에서 바로 관리자 화면으로 갈 수 있게 한다.

## 근거 (2026-11-22, SOOP 클립 10,000개 측정)

- 지금 기준: 자동 898 · 확인 필요 977 · 노래 아님 8,125
- 원곡 가수가 없고 처음 보는 곡명인 자동 공개 77개 중 약 30개가 잡담이다.
- 제목 모양만으로는 가를 수 없다. "귀로-따린", "사미인곡 - 따린" 같은 진짜 노래도 잡담과 모양이 같다.
- 음원 검색 비교
  - iTunes: 한국 스토어 결과가 비어 있다.
  - MusicBrainz: 한국 곡이 많이 빠져 있다.
  - **Deezer**(키 불필요): 위 77개에서 잡담은 0개 통과, 진짜 노래 25개를 찾았다. 못 찾은 진짜 노래는 확인 필요로 간다(잘못 공개되지는 않음).

## 정한 것

### 1. 제목 읽기 보강 (`src/lib/parse-title.ts`)

- **Live**: 곡명 끝의 `Live`/`LIVE`/`라이브`(괄호 유무 상관없이)는 떼고 그대로 노래로 본다. 예: "취한 줄을 모르고 LIVE" → "취한 줄을 모르고".
- **원본**: 제목에 "원본"이 있으면 **노래 아님**(원곡을 튼 클립). 예: "Nobody Knows 원본", "Live 원본".
- **곡명 - 가수**: 곡명 쪽에 다시 하이픈이 있으면 "곡명 - 가수"로 나눈다. 예: "따린 - Fallin - Alicia keys" → 곡 "Fallin", 가수 "Alicia keys". 이건 가수가 확실하게 적힌 것으로 친다.
- **꼬리 잡음 떼기**: 곡명 끝의 `ㄷㄷ`·`ㅋㅋ…`·`ㅎㅎ…`, `많관부`, 6자리 날짜(`260319`), `[짧]` 같은 대괄호 메모.
- **숫자 곡명**: 정리한 곡명이 숫자 1~2자리뿐이면 자동 공개하지 않는다(확인 필요). 예: "따린 놀리기 -1".
- `Parsed`에 `artistSure: boolean`을 더한다.
  - true: 가수가 괄호 "곡명 (가수)", "가수 - 곡명", "곡명 - 가수", "따린 / 곡명 - 가수"로 적힌 경우
  - false: 가수가 없거나, "따린 ○○ - 곡명"의 ○○를 가수로 짐작한 경우(`soloPhrase`). 예: "따린 놀리기"의 "놀리기"

### 2. 자동 공개 조건 (`src/server/verify.ts` 새 파일, `ingest.ts`에서 호출)

제목 읽기 결과가 `auto`인 새 클립은 아래 중 **하나**를 만족해야 공개한다. 하나도 맞지 않으면 `review`(확인 필요)로 둔다.

1. `artistSure`
2. 이미 아는 곡: 공개 무대가 있는 곡(`loadKnownSongs`, 관리자가 승인한 곡 포함)
3. Deezer에서 정규화 곡명이 **정확히 같은** 곡이 나옴

추가 조건:
- 숫자 곡명(1~2자리)은 위 조건과 상관없이 `review`.
- `review`·`not_song` 판정과 방송 단위 판단(`resolveBroadcast`)은 지금 그대로 둔다.

### 3. Deezer 조회 (`src/lib/deezer.ts` 새 파일)

- `GET https://api.deezer.com/search/track?q=<곡명>&limit=25`. `fetch`는 바꿔 끼울 수 있게 해서 시험에 쓴다. 제한 시간은 10초.
- 곡명 비교: 양쪽 다 괄호 안 내용을 빼고 정규화(`norm`)해서 같은지 본다.
- 원곡 가수 고르기: 같은 곡명 결과를 가수별로 묶어 `rank`를 더한다. 1위 가수 합이 2위의 **2배 이상**(또는 가수가 하나뿐)일 때만 그 가수를 쓴다. 아니면 비운다.
  - 예: Take Me To Church → Hozier, 사미인곡 → Seo Moon Tak. "허니"처럼 같은 제목이 여럿이면 비운다.
  - Deezer가 준 이름을 그대로 쓴다(영어 표기일 수 있음). 관리자 화면에서 고칠 수 있다.
- 원곡 가수는 클립 제목에 가수가 없을 때만 채운다. 제목의 가수가 항상 우선이다.
- SOOP에 쓰는 `Throttle`로 동시 2개, 300ms 간격을 지킨다(Deezer 제한: 5초에 50번).

### 4. 검사 결과 저장 (DB)

- 새 표 `title_checks`: `title_norm`(기본 키), `found boolean`, `artist text null`, `checked_at`.
  - 같은 곡명은 Deezer에 다시 묻지 않는다.
  - 못 찾은 결과(`found=false`)는 30일 지나면 다시 묻는다(나중에 음원이 올라올 수 있음).
- `clips`에 `unverified boolean default false`를 더한다. Deezer 오류(응답 없음, 형식 다름)로 판단하지 못해 `review`로 둔 클립에 표시한다.
  - 매일 갱신 마지막에 `unverified`이면서 잠기지 않은 클립을 다시 검사한다. 통과하면 `auto`로 바꾸고 무대를 다시 계산한다.
  - 오류 결과는 `title_checks`에 저장하지 않는다.
- drizzle 마이그레이션으로 추가한다(기존 데이터는 안 바뀜).

### 5. 이미 공개된 클립 다시 검사

- 관리자 화면에 **"자동 공개 다시 검사"** 버튼을 만든다(`AdminTools`, 서버 액션은 `requireAdmin`).
- 대상: `status = auto`이고 `locked = false`인 클립. 관리자가 고친 클립은 건드리지 않는다.
- 방송 단위로 공개한 클립(`viaBroadcast`)은 제외한다(그건 "가수 - 곡명" 규칙이 따로 판단).
- 다시 검사 때 "아는 곡"은 **관리자가 승인한 클립이 있거나 공개 무대가 2개 이상인 곡**으로 좁힌다. 공개 무대 하나뿐이면 그 클립 자신이라 근거가 안 된다(구현 중 추가, 2026-11-22).
- 새 규칙(1장 + 2장)으로 다시 판정한다.
  - 통과 못 하면 `review`로 내린다.
  - "원본"이 붙은 클립은 `not_song`으로 바꾼다.
  - 바뀐 클립의 무대는 다시 계산한다.
- 결과로 "N개 확인 필요로 이동"을 보여준다.
- 대상 중 Deezer를 실제로 부르는 건 가수 없이 처음 보는 곡명뿐이다(측정에서 약 80개). `maxDuration` 300초 안에 끝난다.
- 기존 곡명 정리(잡음 떼기)는 새 클립부터 적용한다. 이미 만들어진 곡 이름은 바꾸지 않는다(곡 합치기·URL이 꼬이지 않게).

### 6. 관리자 로그인 버튼

- 사이트 맨 아래(`footer`)에 작은 **"관리자"** 링크를 넣는다. `/admin`으로 가고, 로그인하지 않았으면 기존대로 `/admin/login`으로 넘어간다.
- `target="_blank"`로 항상 새 탭에서 연다. 일정표 앱 안(iframe)에서는 아이폰 사파리 등이 로그인 쿠키를 막기 때문이다.
- footer는 앱 안에서도 보이므로 앱과 사이트 어디서든 누를 수 있다.

## 바꾸는 파일

- `src/lib/parse-title.ts`: Live·원본·곡명-가수·잡음·숫자 곡명, `artistSure`
- `src/lib/deezer.ts` (새 파일): 조회, 곡명 비교, 가수 고르기
- `src/server/verify.ts` (새 파일): 자동 공개 조건, `title_checks` 캐시, 다시 검사
- `src/server/ingest.ts`: 새 클립 판정에 검사 끼우기, `unverified` 표시
- `src/server/sync.ts`: 매일 갱신 끝에 `unverified` 재검사
- `src/db/schema.ts` + 마이그레이션: `title_checks` 표, `clips.unverified`
- `src/app/admin/actions.ts`, `src/components/AdminTools.tsx`: 다시 검사 버튼
- `src/app/layout.tsx`, `src/app/globals.css`: footer 관리자 링크

## 시험

- 제목 읽기: 예시 제목으로 단위 시험
  - "따린 놀리기 -1" → 숫자 곡명, `review`
  - "따린 - 취한 줄을 모르고 LIVE" → 곡 "취한 줄을 모르고"
  - "따린&마냥 - Nobody Knows 원본" → `not_song`
  - "따린 - Fallin - Alicia keys" → 곡 Fallin, 가수 Alicia keys, `artistSure`
  - "[클립]따린 - 빅마마 체념 중간부분 지림 ㄷㄷ" → 잡음 `ㄷㄷ` 제거
- Deezer: 가짜 응답으로 시험
  - 정확히 같은 곡명만 인정
  - 가수 2배 규칙
  - 오류 시 `unverified`
- ingest(pglite)
  - 잡담 "-따린" 클립 → `review`
  - 아는 곡 → `auto`(Deezer 안 부름)
  - Deezer 찾음 → `auto` + 가수 채움
  - 캐시 재사용
- 다시 검사: 잠긴 클립은 안 바뀜, 통과 못 한 자동 클립은 `review`
- 실제 데이터: 측정 스크립트로 클립 10,000개를 다시 분류해서 전후 숫자와 내려간 클립 목록을 확인한다. 잡담 "-따린" 클립과 "따린 놀리기 -1, -2"가 빠져야 한다.

## 하지 않는 것

- 올리는 사람 신뢰도(방법 3)는 하지 않는다.
- 이미 있는 곡 이름 정리는 하지 않는다.
- 확인 필요(`review`) 클립을 Deezer로 자동 공개하지 않는다. 그쪽 문제는 "누가 불렀는지"라서 음원 검색으로 풀리지 않는다.
